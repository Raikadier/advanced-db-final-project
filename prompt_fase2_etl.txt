BUG CRÍTICO 1 — Type mismatch pd.NA en STG_DiasEntrega y STG_EntregaPuntual
--------------------------------------------------------------------------------
Archivo: etl/transform.py — función transform_orders()

CÓDIGO ACTUAL (problemático):
----------------------------------------------------------------------
def transform_orders(df: pd.DataFrame) -> pd.DataFrame:
    out = df.copy()
    # ...fechas y limpieza...

    # TR-007: días de entrega
    mask_shipped = out["ShippedDate"].notna()
    out["STG_DiasEntrega"] = pd.NA                          # ← BUG: dtype object
    out.loc[mask_shipped, "STG_DiasEntrega"] = (
        (out.loc[mask_shipped, "ShippedDate"] - out.loc[mask_shipped, "OrderDate"])
        .dt.days
    )

    # TR-008: indicador de puntualidad
    mask_both = mask_shipped & out["RequiredDate"].notna()
    out["STG_EntregaPuntual"] = pd.NA                       # ← BUG: dtype object
    out.loc[mask_both, "STG_EntregaPuntual"] = np.where(
        out.loc[mask_both, "ShippedDate"] <= out.loc[mask_both, "RequiredDate"],
        1, 0
    )
    return out
----------------------------------------------------------------------

POR QUÉ FALLA:
  - pd.NA inicializa la columna con dtype=object
  - np.where() devuelve numpy.int64 para las filas calculadas
  - La mezcla de pd.NA y numpy.int64 en la misma columna mantiene dtype=object
  - pyodbc no puede hacer INSERT de una columna object en columnas INT/BIT de SQL Server
  - Resultado: ERROR en todos los 830 INSERTs de STG_ORDERS

CORRECCIÓN REQUERIDA:
  Reemplaza el bloque de transform_orders() aplicando estas reglas:
    - STG_DiasEntrega  → usar None (no pd.NA), castear a pd.Int32Dtype() al final
    - STG_EntregaPuntual → usar None (no pd.NA), castear a pd.Int8Dtype() al final
    - Ambos deben usar pandas nullable integer types para que None se serialice
      como SQL NULL sin romper el tipo

CÓDIGO CORRECTO que debe quedar:
----------------------------------------------------------------------
    # TR-007: días de entrega (solo donde ShippedDate no es NULL)
    mask_shipped = out["ShippedDate"].notna()
    out["STG_DiasEntrega"] = None
    out.loc[mask_shipped, "STG_DiasEntrega"] = (
        (out.loc[mask_shipped, "ShippedDate"] - out.loc[mask_shipped, "OrderDate"])
        .dt.days
    )
    out["STG_DiasEntrega"] = out["STG_DiasEntrega"].astype(pd.Int32Dtype())

    # TR-008: indicador de puntualidad (1=puntual, 0=tarde, NULL=no enviado)
    mask_both = mask_shipped & out["RequiredDate"].notna()
    out["STG_EntregaPuntual"] = None
    out.loc[mask_both, "STG_EntregaPuntual"] = np.where(
        out.loc[mask_both, "ShippedDate"] <= out.loc[mask_both, "RequiredDate"],
        1, 0
    )
    out["STG_EntregaPuntual"] = out["STG_EntregaPuntual"].astype(pd.Int8Dtype())
----------------------------------------------------------------------

Aplica este cambio en etl/transform.py, manteniendo el resto de la función
intacto. No modifiques otras funciones.

MEJORA MENOR — truncate_staging usa DELETE en lugar de TRUNCATE
--------------------------------------------------------------------------------
Archivo: etl/load.py — función truncate_staging()

CÓDIGO ACTUAL:
  def truncate_staging(engine, table_name: str):
      with engine.begin() as conn:
          conn.execute(text(f"DELETE FROM {table_name}"))

CORRECCIÓN:
  def truncate_staging(engine, table_name: str):
      with engine.begin() as conn:
          conn.execute(text(f"TRUNCATE TABLE {table_name}"))

  TRUNCATE TABLE es instantáneo, no registra fila a fila en el log de
  transacciones y resetea páginas de datos. DELETE es O(n) en el log.
